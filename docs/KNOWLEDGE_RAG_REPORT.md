# Knowledge RAG 구축 보고서

흉부 X-ray 진단 지원 에이전트 · Retrieval & Trust Pipeline

작성일: 2026년 8월 30일

---

## 1. 개요

### 1.1 목적

- 본 보고서는 흉부 X-ray 진단 지원 에이전트의 구성요소인 Knowledge RAG의 설계 및
  구현 내용을 기술함
- Knowledge RAG는 영상 모델이 산출한 소견에 외부 임상 근거를 결합하는 역할을 수행함
- Vision 파이프라인이 개별 환자의 영상에서 특정 소견의 존재 여부를 판정하는 데 반해,
  Knowledge RAG는 해당 소견이 갖는 임상적 의미와 후속 조치에 관한 공신력 있는 문헌
  근거를 제공함

### 1.2 기능 범위

- 영상 소견의 임상적 의미 제공
- 감별진단 시 참고할 근거 제공
- 추가 검사 및 확인사항 안내
- 근거 문헌의 출처(citation) 반환

### 1.3 시스템 내 위치

- 검색 결과는 `EvidenceItem(kind=LITERATURE)` 형태로 정규화되어 Trust & Conflict
  Resolver의 입력으로 전달됨
- Vision 파이프라인이 생성하는 Evidence Packet과 동일한 스키마를 사용함
- 이에 따라 양측 담당자는 상대 모듈의 내부 구현을 알지 못하여도 독립적으로 개발을
  진행할 수 있음

## 3. 파이프라인 설계

### 3.1 전체 구성

```
PDF (17건)
  → 텍스트 추출 및 서지 메타데이터 결합      parse.py
  → 토큰 기준 chunking 및 메타데이터 부착     chunk.py
  → 임베딩                                  embed.py
  → 벡터 인덱스 구축                         index.py
  → 검색 및 citation 생성                    search.py
  → EvidenceItem(kind=LITERATURE)
```

- 오프라인 배치 구간(parse~index)과 온라인 질의 구간(search)을 분리하여 구성함
- 분리 근거는 양자의 실행 주기가 상이하며, 배치가 API 서버와 독립적으로 재실행될 수
  있어야 하기 때문임

### 3.2 텍스트 추출

- 텍스트는 페이지 단위로 추출하며 페이지 번호를 함께 보존함
- 페이지 번호 보존 근거
  - citation이 문서 단위에 머무를 경우 사용자가 근거를 원문에서 확인할 수 없음
  - 예: 184쪽 분량의 WHO 결핵 진단 지침을 문서 단위로만 인용하면 해당 근거의 위치를
    확인할 방법이 없음
  - 인용의 검증 가능성 확보를 위하여 페이지 단위 추적을 채택함
- 추출 텍스트에 대하여 다음 정규화를 적용함

| 처리 | 내용 | 근거 |
|---|---|---|
| 하이픈 분철 복원 | `pneumo-\nthorax` → `pneumothorax` | 미처리 시 해당 용어가 검색에서 영구 누락됨 |
| 단일 개행의 공백 치환 | 줄바꿈을 공백으로 변환 | PDF의 개행은 시각적 배치이며 문장 경계가 아님 |
| 문단 경계 보존 | 연속 개행 2회 이상은 유지 | 의미 단위 구분 정보의 상실을 방지함 |

- 추출 문자 수 50자 미만 페이지는 표지 또는 도판 전용 면으로 판단하여 제외함

### 3.3 Chunking

| 파라미터 | 값 |
|---|---|
| Chunk 크기 | 700 토큰 |
| Overlap | 100 토큰 |
| 토크나이저 | cl100k_base |

- chunk는 페이지 경계를 넘어 생성하되 각 chunk의 시작 페이지를 기록함
- 페이지마다 절단할 경우 문단이 중간에서 끊긴 chunk가 다수 발생하여 검색 품질이
  저하되기 때문임

### 3.4 참고문헌 구간 제거

- 서지 나열은 지식이 아닌 메타데이터에 해당하며 인덱스 포함 시 검색 결과를 오염시킴
- 다음 패턴의 출현 밀도를 텍스트 길이로 정규화한 점수를 산출하여 판별함
  - `et al.` 표기의 출현
  - `숫자. 대문자` 형태의 번호 매김 인용
  - `연도;` 또는 `연도:` 형태의 저널 표기
- 임계값 0.3 적용 결과 전체 899개 chunk 중 127개(14.1퍼센트)가 참고문헌 구간으로
  판별되어 제외됨
- 최종 772개 chunk를 확보함
- 임계값 부근 표본에 대하여 육안 검증을 수행하였으며 본문의 오탈락은 확인되지 아니함

### 3.5 Chunk 메타데이터

- 각 chunk는 citation 생성에 요구되는 정보를 모두 보유함

```json
{
  "chunk_id": "GL003_p0004_c002",
  "doc_id": "GL003",
  "title": "community-acquired pneumonia",
  "document_type": "guideline",
  "organization": "ATS / IDSA",
  "year": 2019,
  "target_coverage": ["Pneumonia", "Consolidation", "Lung Opacity"],
  "page": 4,
  "section": "Diagnosis",
  "source_url": "https://...",
  "n_tokens": 700
}
```

- 섹션 제목은 정규표현식 기반으로 탐지하였으며 전체 899개 chunk 중 53개(5.9퍼센트)
  에서만 식별됨
- PDF는 heading을 구조적으로 표기하지 아니하므로 탐지율에 한계가 존재함
- 미탐지 시 `null`을 부여하였고 추정값으로 대체하지 아니함
- 부정확한 섹션명은 부정확한 citation으로 직결되기 때문임

### 3.6 임베딩

- 임베딩 모델로 OpenAI text-embedding-3-large(3,072차원)를 채택함
- 의학 도메인 특화 모델인 MedCPT를 채택하지 아니한 근거
  1. MedCPT Article Encoder의 입력 한계가 512 토큰이므로 본 파이프라인의 700 토큰
     chunk가 절단됨
  2. MedCPT는 PubMed 초록 쌍으로 학습된 모델로서 본 코퍼스인 진료지침 본문 산문과
     텍스트 분포가 상이함
  3. 코퍼스 규모가 537,059 토큰으로 제한적이어서 전량 임베딩 비용이 약 0.07 USD에
     그침
- 다만 도메인 특화 모델의 우위 가능성을 배제할 수 없으므로, Phase 2에서 동일 평가셋을
  사용하여 MedCPT와 비교 측정할 계획임

### 3.7 Rate limit 대응

- 구축 과정에서 계정 등급의 분당 토큰 한도(40,000 TPM)를 초과하여 초기 배치가 HTTP
  429로 실패함

**원인**

- 배치를 chunk 개수 기준(128개)으로 분할한 결과, chunk 길이 편차로 인하여 단일 요청이
  104,455 토큰에 도달하여 한도를 초과함

**대응**

1. 배치 분할 기준을 개수에서 토큰 예산으로 변경함
2. 응답 헤더(`x-ratelimit-remaining-tokens`, `x-ratelimit-reset-tokens`)를 이용한
   송신 속도 제어를 도입함
3. 잔여 429에 대하여 지수 백오프 재시도를 적용함
4. 텍스트 해시를 키로 하는 임베딩 캐시를 도입하여 배치 중단 시 기 완료분을
   재사용하도록 함

**속도 제어의 개선**

- 초기 구현은 60초 롤링 윈도우를 클라이언트에서 자체 추정하는 방식이었으나, 실측 결과
  한도의 약 50퍼센트만을 활용하는 것으로 확인됨
- 원인은 OpenAI의 토큰 버킷이 60초 주기로 일괄 초기화되는 것이 아니라 연속 리필되는
  구조(40,000/분, 약 666 토큰/초)라는 점에 있음
- 대용량 배치는 "버킷 충전 대기 후 일시 소진" 패턴을 유발함
- 이에 배치 크기를 8,000 토큰으로 축소하고, 대기 시간을 `reset` 헤더 값이 아닌 다음
  배치에 대한 부족분과 리필 속도로부터 산출하도록 수정함
- `reset` 헤더는 버킷이 가득 차기까지의 시간을 의미하므로 이를 그대로 적용할 경우
  필요 이상의 대기가 발생함

**응답 정렬**

- 배치 응답은 `index` 필드를 기준으로 재정렬함
- 순서가 어긋날 경우 chunk와 벡터가 불일치하게 됨
- 이는 오류를 발생시키지 아니한 채 잘못된 검색 결과를 반환하는 형태로 나타나므로
  탐지가 어려움

### 3.8 인덱스

- 벡터 데이터베이스로 Qdrant를 채택하고 코사인 거리를 적용함
- 컬렉션은 다음과 같이 분리함

| 컬렉션 | 용도 |
|---|---|
| `knowledge_guidelines_reviews` | 문헌 근거 |
| `radiology_cases` | 증례 근거 (별도 구축) |

- 분리 근거는 양자의 검색 목적과 메타데이터 스키마가 상이하다는 점임
- 로컬 파일 모드로 구성하되 환경변수 `QDRANT_URL` 지정만으로 서버 모드로 전환되도록
  클라이언트를 추상화함
- 이에 따라 배포 시 코드 변경이 요구되지 아니함
- 재색인은 컬렉션 전체 삭제 후 재생성 방식으로 수행함
- 부분 갱신 방식은 `chunk_id` 변경 시 구 벡터가 잔존하여 검색 결과에 유령 문서로
  노출되는 문제를 유발함

### 3.9 검색 및 품질 점수

- Phase 1은 dense 검색 단독으로 구성함
- 메타데이터 필터를 통하여 observation 및 문서 유형 기준의 범위 제한을 지원함
- 검색 결과는 `EvidenceItem`으로 변환되며 `quality` 필드는 다음 식으로 산출함

```
quality = 권위도(문서 유형) × 신선도(발행 연도)
```

| 문서 유형 | 권위도 |
|---|---:|
| guideline | 1.00 |
| review | 0.85 |
| review/reference | 0.80 |

- 신선도는 반감기 12년의 지수 감쇠를 적용하고 하한을 0.3으로 설정함
- 2009년 리뷰와 2024년 진료지침에 동일 가중을 부여할 경우 Trust 계산이 성립하지
  아니하기 때문임
- 발행 연도 미상 문서에는 0.7을 부여하였으며 최신 문서와 동일하게 취급하지 아니함

## 4. 검증

### 4.1 단위 테스트

- 17개 테스트를 작성하여 전량 통과를 확인함

| 구분 | 검증 내용 |
|---|---|
| 텍스트 정규화 | 하이픈 분철 복원, 개행 치환, 문단 경계 보존 |
| 참고문헌 판별 | 서지 나열의 양성 판정, 본문의 음성 판정 |
| Chunking | 토큰 예산 준수, 페이지 추적, 메타데이터 전파 |
| 품질 점수 | guideline > review, 최신 > 과거, 연도 미상 < 최신의 단조성 |
| Citation | 필수 필드 존재 여부 |

### 4.2 검색 품질 평가

#### 4.2.1 평가 설계

- 테스트 쿼리 8개를 평가셋으로 사용함
- 정답 문서 집합은 `sources.csv`의 `target_coverage` 필드로부터 도출함
  - 예: "기흉 소견" 질문의 정답은 `target_coverage`에 `Pneumothorax`를 포함하는 문서
- 코퍼스는 영문이나 실사용 질의는 한국어로 입력되므로 양 언어를 모두 측정함
- 지표는 Hit@k(정답 문서가 상위 k건에 포함되는 비율)와 MRR(정답의 역순위 평균)을 사용함

#### 4.2.2 측정 결과

| 지표 | 영어 질의 | 한국어 질의 | 차이 |
|---|---:|---:|---:|
| Hit@1 | 0.875 | 0.625 | -0.250 |
| Hit@3 | 1.000 | 0.625 | -0.375 |
| Hit@5 | 1.000 | 0.750 | -0.250 |
| Hit@8 | 1.000 | 0.750 | -0.250 |
| MRR | 0.938 | 0.656 | -0.282 |
| 1위 결과 평균 유사도 | 0.656 | 0.455 | -0.201 |

- 영어 질의에서는 8개 쿼리 전건에 대하여 정답 문서가 상위 3건 이내에 검색됨
- 8개 중 7개는 1위로 검색되었으며, 잔여 1개(심비대·폐부종 동반 맥락)도 2위에 위치함
- 한국어 질의에서는 Hit@8이 0.750으로 하락하였고 MRR은 0.282 감소함

#### 4.2.3 한국어 질의 실패 사례

- 8개 중 2개가 상위 8건 내 정답 미포함으로 실패함

| 질의 | 정답 문서 | 검색 결과 | 1위 유사도 |
|---|---|---|---:|
| 흉부 X-ray에서 기흉을 시사하는 주요 소견은? | GL004, RV002, RV007, RV008 | RV006 8건 | 0.541 |
| 늑골 골절이 의심될 때 적절한 영상검사는? | GL007 | GL002 8건 | 0.368 |

- 두 실패 사례는 공통적으로 상위 8건이 단일 문서로 채워지는 양상을 보임
- 이는 질의 벡터가 특정 문서 전반과 약한 유사도를 형성할 뿐, 해당 소견을 다루는
  문서를 변별하지 못한 결과로 판단됨
- top-8 내 고유 문서 수는 전체 평균 2.50건이나 실패 사례에서는 1.00건으로 나타남
- 특히 늑골 골절 질의의 1위 유사도는 0.368로 전체 최저값이며, 정답 문서인 GL007은
  코퍼스 내 chunk 10건에 불과한 최소 밀도 문서임
- 근거 밀도가 낮은 소견에서 언어 간 성능 격차가 확대되는 경향이 관측됨

#### 4.2.4 원인 분석

- 임베딩 모델은 다국어를 지원하나, 한국어 질의와 영문 문서 간 유사도가 동일 언어 쌍에
  비하여 전반적으로 낮게 형성됨
- 1위 결과의 평균 유사도가 0.656에서 0.455로 하락한 점이 이를 뒷받침함
- 유사도 분포가 압축되면 정답 문서와 비정답 문서 간 변별력이 저하되며, 이는 특정 문서가
  상위를 독점하는 형태로 나타남

#### 4.2.5 대응 방안

- 동일 질문의 영문 표현에서는 Hit@8이 1.000으로 회복됨
- 이는 질의 번역(query translation)이 유효한 대응 수단임을 지시함
- Phase 2에서 다음을 적용할 계획임

| 방안 | 기대 효과 |
|---|---|
| 질의 번역 후 검색 | 언어 간 유사도 격차 해소. 본 측정에서 Hit@8 1.000 확인 |
| BM25 sparse 검색 병행 | 의학 용어 및 약어의 표층 일치 확보 |
| RRF 순위 융합 | 단일 문서 독점 완화 |
| Cross-encoder reranking | 질의-문서 쌍의 직접 비교를 통한 변별력 보강 |

- 다만 질의 번역은 지연 시간과 번역 오류라는 비용을 수반하므로, Phase 2에서 번역 방식과
  다국어 임베딩 모델 교체를 비교 측정한 후 채택 여부를 결정함

## 5. 한계 및 향후 계획

### 5.1 현재 한계

| 항목 | 내용 | 개선 방향 |
|---|---|---|
| 언어 간 성능 격차 | 한국어 질의 Hit@8 0.750 (영어 1.000) | 질의 번역 또는 다국어 임베딩 모델 교체 |
| 근거 밀도 편중 | 3개 소견이 단일 문서에 의존. 저밀도 소견에서 언어 격차가 확대됨 | 해당 영역 문헌 추가 수집 |
| 검색 방식 | dense 단독 | BM25 병행. 의학 약어 및 고유명사는 sparse 검색이 우월함 |
| 단일 문서 독점 | 실패 사례에서 top-8이 1개 문서로 채워짐 | RRF 융합 및 reranking 적용 |
| 섹션 탐지율 | 5.9퍼센트 | PDF 구조 정보 부재에 기인함. 레이아웃 기반 파서 도입 시 개선 가능 |

- 상기 항목 중 언어 간 성능 격차가 최우선 개선 대상임
- 서비스의 실사용 질의가 한국어로 입력되는 점을 고려할 때, 현재 성능은 4건 중 1건에서
  근거 문헌을 확보하지 못하는 수준에 해당함

### 5.2 Phase 2 계획

- 우선순위는 4.2절 측정 결과에 근거하여 다음과 같이 설정함

| 순위 | 과제 | 근거 |
|---:|---|---|
| 1 | 한국어 질의 대응 (번역 방식 대 다국어 모델 비교) | Hit@8 0.750으로 최대 성능 손실 지점 |
| 2 | BM25 sparse 검색 추가 및 RRF 융합 | 단일 문서 독점 현상 완화 |
| 3 | Cross-encoder reranking 적용 | 유사도 압축 구간의 변별력 보강 |
| 4 | MedCPT와의 임베딩 성능 비교 측정 | 도메인 특화 모델의 우위 여부 검증 |

- 각 단계 적용 후 동일 평가셋으로 재측정하여 개선 효과를 정량 확인함

### 5.3 Phase 3 계획

- Query rewrite 및 decomposition
- 근거 충분성 평가(CRAG)와 재검색
- Web search fallback

### 5.4 Case RAG 진행 상황

- Case RAG는 문헌 코퍼스와 별도의 corpus로 구축함
- MIMIC-CXR에 대한 PhysioNet 이용 승인(DUA)이 완료되어 해당 데이터로 구축을 진행함
- 대체 후보였던 NLM Open-i는 사용하지 아니함

| 항목 | 규모 |
|---|---:|
| Study | 227,835 |
| 이미지 | 377,095 |
| 환자 | 65,379 |
| 섹션 파싱 성공 | 227,781 |

- 검색 대상 텍스트는 Findings와 Impression을 결합하여 구성하며, 정형 섹션이 없는
  리포트는 파서의 fallback 텍스트를 사용함
- Qdrant 컬렉션은 `radiology_cases`로 분리함
- 상세 내용은 별도 보고서로 작성 예정임

**데이터 취급**

- MIMIC-CXR 및 MIMIC-IV-ED는 PhysioNet credentialed 데이터로서 재배포가 금지됨
- 원본 데이터와 파생 인덱스는 저장소에 포함하지 아니하며, 승인된 환경에만 보관함
- Qdrant payload에 `subject_id`를 저장하지 아니함. 유사 사례 검색에 필요한 정보는
  소견 내용과 study 식별자이며 환자 식별자가 아니기 때문임
