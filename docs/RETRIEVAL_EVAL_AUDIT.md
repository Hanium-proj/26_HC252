2026-09-22. ACK2026_R7의 Hit@8 근거를 확인하기 위해 기존 평가 질문을 재실행했다. **새로운 독립 평가셋을 만든 실험이 아니다.** 질문은 8개이며 세 가지 검색 조건으로 총 24회 검색했다.

## 실행 조건

- 검색: `text-embedding-3-large`, dense 검색, 상위 8문단. BM25·리랭킹 미사용.
- 영어 원문: 평가 코드에 미리 작성된 영문 질문.
- 한국어 직접: 평가 코드의 한국어 질문을 그대로 임베딩.
- 자동 번역: 동일 한국어 질문에 기존 `translate_query()` 적용(`gpt-4o-mini`, temperature=0), 번역문을 dense 검색. 번역문도 결과 JSON에 저장.

- 결과 파일: `backend/outputs/hitrate_audit/existing_8_20260922_133649.json`.
- 24회 모두 오류 없이 상위 8문단 반환. 저장 결과의 순위·집계와 실제 번역문 생성을 확인했다.

## 현재 지표가 측정하는 것

현재 채점은 검색 문단의 `doc_id`가 미리 지정한 정답 문서 집합에 속하는지 검사한다. 해당 문단 자체가 질문에 답하는지는 검사하지 않는다. 따라서 결과는 **정답 문서에 속한 문단의 적중률**이며, 답변 근거 문단의 적중률이나 답변 정확도가 아니다.

정답 문서 범위의 영향을 확인하기 위해 균등 무작위 문단 추출의 기대값도 계산했다. 문단 전체 N=772, 정답 문서들에 속한 문단 수를 M이라고 하면, 중복 없이 임의의 8문단을 뽑을 때 한 번 이상 적중할 확률은 다음과 같다.

```text
P(hit@8) = 1 - C(N-M, 8) / C(N, 8)
```

이는 실제 무작위 검색기의 실측 결과가 아니라 **현재 코퍼스와 채점 기준에 대한 조합론적 기대값**이다. 실제 임베딩 검색의 문단 간 상관이나 중복 문서 분포를 모사한 값도 아니다. 문서 집합이 넓은 일부 질문에서는 Hit@8만으로 검색 품질을 구별하기 어렵다는 진단에 사용한다.

## 평가셋 확대 방향

1. 기존 8개는 개발·진단용으로 유지하고, 서로 다른 정보 요구를 가진 새 질문 약 60개를 별도 평가용으로 구성한다. 60개는 이번 프로젝트의 제안 규모이며 보편적인 기준이 아니다.
2. 질문별 답변 근거를 페이지·문단으로 지정하고 검수한다. 자동 생성 초안은 검수된 정답과 구분한다. 문서 수준 적중은 보조 지표로 유지할 수 있다.
3. 한영 질문 쌍으로 같은 정보 요구를 비교한다. 한영 60쌍을 독립 질문 120개로 세지 않는다.
4. Hit@1·3·8 및 MRR@8을 함께 보고한다. 실제 에이전트가 소견당 문헌 3건을 사용하므로 Hit@3를 주요 지표에 포함한다.
5. 검색 설정을 평가 전에 고정하고, 결과를 보고 잘 맞는 질문만 선택하거나 정답을 유리하게 바꾸지 않는다. 문단 관련성 검수는 질문의 정보 요구에 근거해 수행한다.

R7 본문의 8/8·6/8 표기는 표본 수를 드러내지만 평가 설계를 개선하지는 않는다. 초록에는 아직 1.000·0.750이 남아 있어 본문과 표기를 맞출 필요가 있다. 이번 작업에서는 논문 DOCX, 기존 평가 코드 및 기존 보고서 수치를 변경하지 않았다.
