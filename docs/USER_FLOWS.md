# 사용자 흐름과 상태 계약

2026-10-25 · 로컬 단일 사용자 연구 워크스페이스

## 기본 흐름

검사 등록 → 영상 분석 → 근거 확인 → 질문·검토. 문헌 검색은 어느 단계에서도 사용할 수 있다.
화면 상단의 검토 흐름은 현재 위치와 실제 분석 가능 상태를 표시한다. 단순히 방문했다는 이유로 근거 검토를 완료 처리하지 않는다.

## 시나리오별 동작

| 상황 | 동작 | 이번 검증 |
|---|---|---|
| 검사 업로드 | 등록된 검사 ID로 분석 화면 이동 | 기존 실제 업로드 흐름 유지, 경로 코드 검토 |
| 검사 선택 후 탭 이동 | 모든 내부 링크에 study ID 전달 | 브라우저 확인 |
| 새로고침·직접 링크 | URL의 검사 ID 기준 복원 | 브라우저 확인 |
| 없는 검사 링크 | 다른 검사로 자동 대체하지 않고 오류와 목록 복귀 제공 | 브라우저 확인 |
| 분석 전 근거/에이전트 진입 | 분석 화면으로 안내; 일반 문헌 질문과 영상 기반 질문 구분 | 구현·코드 검토 |
| 임상 조건 편집 중 탭 이동 | 검사별 초안 유지; 다른 탭에서는 저장된 결과임을 명시 | 브라우저 확인 |
| 편집 취소 | 서버 저장값으로 초안 복원 | 브라우저 확인 |
| 이전 영상 없음 | 같은 익명 환자 식별자를 두 검사에 저장해야 함을 안내 | 구현·코드 검토 |
| 분석 중 탭 이동 | 공유 provider에서 요청 계속 실행; 전역 진행/완료/오류 알림 | 실제 모델 호출 후 다른 탭에서 완료 확인 |
| 분석 중 재실행 | 검사 ID별 잠금으로 중복 요청 방지 | 구현·코드 검토 |
| 근거 소견 변경 | 검사별 레이어·대상·표시 여부 유지 | 구현·코드 검토 |
| 소견에서 문헌으로 이동 | 해당 소견 검색어 준비; 사용자가 검색 실행 | 브라우저 확인 |
| 문헌에서 AI로 이동 | 동일 검사 유지, 검색 주제를 질문 초안으로 전달 | 브라우저 확인 |
| AI 질문 초안이 이미 있음 | 기존 내용을 지우지 않고 추가 검토 질문을 붙임; 중복 질문 제거 | 구현·코드 검토 |
| 검색 후 다른 탭/뒤로가기 | 검사별 검색어·범위·결과 복원 | 실제 검색 후 브라우저 확인 |
| 검색 조건만 변경 | 이전 결과라는 안내 표시; 검색 실행 시 갱신 | 구현·코드 검토 |
| 답변 중 이동 | 응답 중지 및 받은 내용을 불완전 답변으로 보관, 질문 재입력 부담 감소 | 기존 중지 검증 및 코드 검토 |
| 재분석 후 대화 | 분석 완료 시각별 대화 분리; 이전 기록은 읽기 전용으로 펼침 | 구현·코드 검토 |
| 두 검사 사이 이동 | ID별 초안/검색/질문/근거 상태 분리 | 코드 검토; 다중 실제 검사 브라우저 테스트는 미수행 |

## 보존 범위

- 저장된 영상, 임상 조건, 분석 결과: 기존 서버 저장소에 유지.
- 선택한 검사: URL의 불투명 ID로 식별. 임상 메모와 질문은 URL에 넣지 않는다.
- 미저장 초안, 검색 화면, 대화: 현재 페이지 세션 메모리에서 유지. 새로고침/새 탭에서는 초기화된다. 브라우저 영구 저장소에 임상 내용을 추가 저장하지 않는다.
- 분석 작업 추적: 현재 세션 내 화면 이동에서 유지. 새로고침 후 실행 상태를 복구하는 서버 작업 API는 아직 없으므로 진행 안내에 새로고침을 피하도록 표시한다.
- 에이전트 생성은 화면 이동 시 중지되며, 영상 분석과 동작 차이를 화면에 명시한다.

## 검증

ESLint, 프로덕션 빌드 및 TypeScript, git diff --check 통과. API 결과와 실제 모델·문헌을 사용해 주요 화면 이동 흐름을 확인했으며, 모든 예외 상황을 실기기에서 검증했다는 의미는 아니다.

좁은 인앱 브라우저에서도 다섯 단계가 가로 스크롤 없이 표시되는 것을 확인했다. 화면 증거: backend/data/verification/workflow-connected.png (Git 제외).
